# Asterism core product audit

10 November 2026. Baseline: the v1.2.0 source on `main`, reviewed as a Markdown reader, editor, and rich text converter for browser, Electron, and experimental Tauri. The changes in this checkout are not in the v1.2.0 download. This audit distinguishes source inspection, desktop interaction, and untested behavior.

## Product model

`state.markdown` is the document source. **Read** renders it without editing. **Edit** presents a formatted editor and Markdown source editor for the same document. Opening a Markdown file begins in Read; opening it does not convert the file. Importing HTML or plain text converts it to Markdown. Before the first formatted edit, a source-fidelity guard detects common source-only syntax: HTML comments and raw HTML blocks such as `<details>` (excluding code and autolinks), link and footnote definitions, and YAML front matter outside fenced code blocks. The user can stay in Markdown or explicitly convert, with the original source restorable during that session only. The product contract is exact source in the Markdown pane and explicit conversion for formatted editing; the guard is not universal, and unrecognized constructs can still be rewritten.

This scope supports one local document at a time. Asterism does not need a vault, backlinks, plugins, AI writing, collaboration, or publishing integrations to meet its promise.

## Remaining work, ranked

1. **P1 · Defined source-conversion expectations.** Exact source belongs in the Markdown pane; formatted editing is an explicit conversion. The guard catches common source-only syntax, including raw HTML, but is not universal. Define the supported syntax expectations and add representative CommonMark/GFM conversion fixtures, with preservation improvements for constructs users expect to survive. A universal byte-perfect round trip is not a release requirement.
2. **P1 · Browser file access and leave protection.** Browser Save downloads a copy, and the ordinary file input gives no folder access for resolving a README's nearby images or Markdown links. The desktop bridge covers those cases. A `beforeunload` guard exists for Auto-save off, but browser automation did not show a visible prompt on tab close. If the browser is promoted as a primary offer, add scoped browser file access and verify the leave guard, or clearly describe the limits at the entry point.
3. **P2 · Heading jump.** In-document table-of-contents links work, but long files without such links lack a compact heading jump control. [Bear's outline](https://bear.app/faq/how-to-use-the-info-panel-table-of-contents-and-backlinks-in-bear/) and [iA Writer navigation](https://ia.net/writer/support/library/navigation) show restrained options.
4. **P2 · Copy formatted text.** Asterism copies Markdown; there is no explicit formatted-copy action from Read. Add one if normal selection and Copy proves inadequate. [Bear's Copy As](https://bear.app/faq/copy-portions-of-notes-as-html-rtf-txt-or-markdown/) is a reference.

Auto-save off stops future recovery snapshots but retains the last local snapshot until **Clear all** in Settings. Recovered drafts can offer **Reconnect file** on native Markdown drafts. The user must select the same path, and reattachment proceeds only if the raw file still matches the exact stored baseline; otherwise Save As remains the path to save. The recovery snapshot remains detached until that explicit selection. The desktop shells ask Cancel or Discard Changes before closing unsaved work while Auto-save is off; Electron's actual dialog was exercised, and Tauri's implementation is compile-checked.

## Verification and limits

- Inspected the parser, sanitizer, editor sync, persistence, file opening, Electron and Tauri bridges, menus, and security boundaries.
- In Chrome, checked Markdown editing, match navigation and zero results, replace and Undo, Reader switching, typography, opening a browser file into Read, and restored local content opening into Read.
- In an isolated Electron source run, checked Open into Read, Command-F and menu actions, Save in place, empty-file Save, Save As, and task checkboxes. A second isolated run checked nearby PNG rendering, a bare relative Markdown link, a relative image path surviving a formatted edit and Save, external edit Cancel/overwrite behavior, a heading link jumping in a long document, recovered-draft labeling, and the native Cancel/Discard dialog on both Quit and window Close.
- Two isolated Electron smoke scripts for source-fidelity guarding and recovered-draft reattachment pass under the approved unsandboxed execution. The reattachment smoke test mocks the desktop bridge, so the actual file-picker IPC flow was not runtime verified. These results support the mitigation, not a full source round-trip or release-complete claim.
- Both Electron smoke scripts pass, including the raw HTML `<details>`/`<summary>` guard and restore regression; the source-fidelity smoke passed again after the latest implementation patch. Safe code-language classes survive sanitization and formatted conversion, with JavaScript, C++, and C# covered. The guard remains a mitigation and the reattachment smoke test mocks the desktop bridge, so native file-picker IPC has not been runtime verified.
- Theme inspection passed for Light, Dark, and Auto, including computed code, base, keyword, and string colors; representative code contrast is at least 4.5:1. Paper, Sage, and Midnight selection persists, Auto responds to native appearance changes, Markdown remains unchanged, and Settings fits at 390 px without overflow. Settings selection retains keyboard focus. Theme controls and options were present in the packaged app; actual palette selections were exercised in the isolated real renderer. The single syntax stylesheet now prevents dark colors from leaking into light mode.
- The final local Apple Silicon preview is at `dist/preview-20261110/mac-arm64/Asterism.app`. It includes the latest language-class patch, was ad-hoc signed, passed `codesign --verify --deep --strict`, and launched from the packaged app. It is not notarized or published. A Chrome run confirmed the Auto-save off status, but its automated tab close did not display a browser leave prompt.
- Tauri Rust tests cover relative-path validation, raster signatures, and changed/deleted file conflict detection. `cargo check`, `cargo fmt --check`, JavaScript syntax, and diff whitespace checks pass. Tauri desktop interaction has not been exercised on this machine.
- Search is case-insensitive. It counts all matches and highlights at most 300 near the active match to keep long documents responsive.

## Website decision

A one-page site is worthwhile after the core file behavior is verified and a usable preview build is available to download. Today the README is the only entry point for the browser version, and it asks people to clone the repo. The page could host that same app at `/app/`, with no second copy of the source. Use a real app screenshot, **Open in browser** and **Download Mac preview** actions, and a clear unsigned Apple Silicon note. Explain Read, Edit, and rich text conversion in three short steps; note browser file limits and that linked remote images can load. The static Cloudflare pattern used for Mornumi is sufficient. A larger marketing site would add maintenance without helping the core workflow. No website was deployed in this pass.
